LTE 3GPP指标(1) - 功率 (Power)

分类： 学习笔记
标签： 3GPPLTE

日期：2026-01-23 00:12:01

[toc]

总览

Level 1: 入门级 - 只要电路通了就能过
关键词： 功率 (Power)
涉及章节： 36.101 Clause 6.2 & 6.3
这一层最简单，主要看你的 PA（功率放大器）能不能正常工作，通路是不是通的。

指标名称 中文名 难度 一句话解释 硬件看什么
Max Output Power 最大输出功率 ⭐ 手机能不能喊出 23dBm？ 检查 PA 供电、PA 输入功率、通路损耗。
Min Output Power 最小输出功率 ⭐ 手机能不能把声音压到 -40dBm 以下？ 检查 PA 的增益控制范围，防止“关不严”。
Transmit OFF Power 关断功率 ⭐ 不发信号时，能不能彻底闭嘴？ 检查 PA 的 Enable 信号时序。
On/Off Time Mask 开关时间蒙皮 ⭐⭐ 功率升起来和降下去的速度对不对？ 这是一个时域指标，检查 PA 的电源和控制信号的上升/下降沿。
Absolute Power Control Tolerance 绝对功率控制容限 ⭐⭐
  • 通关标志： 你的板子能连上综测仪，且功率显示正常。

一、UE Maximum Output Power (UE 最大输出功率)

1. 文档索引

  • 章节位置： Clause 6.2.2 (P268)
  • 测试条件： Table 6.2.2.4.1-1 (P271)
  • 测试标准： Table 6.2.2.5-1 (P273)

2. 核心描述

这是手机发射机的“嗓门上限”。
测试时，综测仪会发送 TPC (Transmit Power Control) 指令，命令手机 “All Up”（不断增加功率），直到手机达到其硬件或软件设定的饱和点。

  • 注意： 此项测试专门寻找 MPR = 0 的场景，即 PA 没有任何回退、火力全开的状态。因此，测试配置通常选用 QPSK 调制，搭配 1 RB（测边缘能力）或 部分 RB（测核心推力），而不是 Full RB。

3. 测试目的

  • 保证覆盖范围： 验证手机在小区边缘（弱信号区域）能否以足够的功率发射信号，确保不掉线。
  • 验证硬件极限： 确认 PA (功率放大器) 的物理输出能力、电源供电能力以及射频前端通路的插损（Insertion Loss）是否满足设计要求。
  • 合规性： 确保发射功率不超过规定值，避免干扰其他设备（同时也为了省电）。

4. 常见问题

  • 功率偏低 (Fail Low)：
    • 路径损耗大： 检查双工器、开关、匹配电路的焊接是否良好，或者线缆损耗补偿是否正确。
    • 电源撑不住： 在大功率发射瞬间，VBAT 电压是否跌落过大（IR Drop），导致 PA 供电不足。
    • PA 选型错误： 如果你是 HPUE (Class 2, 26dBm) 的项目，却选了普通 23dBm 的 PA。
  • 高低频差异大：
    • 如果在 RB#0 (低频) 功率合格，但在 RB#Max (高频) 功率偏低，通常是因为滤波器或双工器的频响曲线在边缘滚降太快，或者匹配电路只优化了中心频点。
  • 功率过高 (Fail High)：
    • 校准（Calibration）没做好，或者开环功率控制参数配置错误。

二、MPR (Maximum Power Reduction, 最大功率回退)

1. 文档索引

  • 章节位置： Clause 6.2.3 (P336)
  • 测试条件： Table 6.2.3.4.1-1 (P338)
  • 测试标准： Table 6.2.3.5-1 (P340)

2. 核心描述

“为了保命，主动认怂”。
MPR 是协议赋予手机的一种**“特权”**。
当手机发射高阶调制信号（如 16QAM/64QAM）或者大带宽（Full RB）时，信号的 PAPR (峰均比) 会变大。

  • 如果不回退功率：PA (功放) 会为了顶住峰值而进入饱和区，导致削顶，从而导致 ACLR (邻道泄漏) 和 EVM 挂掉。
  • MPR 机制： 协议允许你在这些难搞的场景下，把最大发射功率降低一点点（比如降低 1dB 或 2dB），以换取更好的线性度。
    背诵口诀 (基于 Table 6.2.3-1)：
  • QPSK: 只要不是特别宽 (Full RB)，通常 MPR = 0 (不回退，必须发 23dBm)。
  • 16QAM: 稍微有点难搞，允许 MPR <= 1dB (发 22dBm 就算合格)。
  • 64QAM: 很难搞，允许 MPR <= 2dB (发 21dBm 就算合格)。

3. 测试目的

  • 平衡术验证： 验证手机是否只在“必要”的时候才降低功率。
    • 如果是 QPSK 小带宽，你不能乱降功率，必须保证覆盖。
    • 如果是 64QAM 大带宽，你要适度降功率，防止干扰邻居。
  • 软件逻辑检查： MPR 通常是由软件里的 NV (Non-Volatile) 参数 或 功率回退表 控制的。测试是为了看这表填没填对。

4. 常见问题

问题 A：该退没退 (Fail ACLR)

  • 现象： 在 16QAM/64QAM Full RB 下，功率依然死顶在 23dBm，结果 ACLR 炸了，EVM 炸了。
  • 原因： 软件里的 MPR 表格没配置，或者 PA 的特征曲线没调好，软件以为 PA 很强能扛住，结果 PA 扛不住。
    问题 B：退得太多 (Fail Max Power)
  • 现象： 协议只允许退 1dB (Limit > 22dBm)，结果你退了 3dB (实测 20dBm)。
  • 原因： 射频链路插损过大，或者软件里的 Power Limit 设得太保守。

5. 其他

MPR 是 “Limit” (限值)，不是 “Target” (目标值)！

  • 协议说 MPR <= 1dB，意思是：“兄弟，这活儿挺累，我允许你偷懒少搬 1 块砖。”
  • 情况 1 (普通手机): 既然允许偷懒，那我就少搬 1 块，发 22dBm。 -> Pass。
  • 情况 2 (机皇/高端 PA): 我身体好，我 PA 线性度牛逼，即使是 64QAM 我也不回退，我照样发 23dBm，而且 ACLR 还能过。 -> Pass！而且是 Great Pass！
    所以，MPR 是允许你变弱的底线，而不是强制你变弱。 如果你的板子不回退也能过 ACLR，那是你本事大，不用强行把功率降下去。

没问题，兄弟！你找对了，Clause 6.2.3 就是 MPR 的老家。
之前咱们是在讲 Max Power 的时候顺带提了一嘴，但既然标准里把它单独列了一章，那咱们就必须给它一个“正式编制”。把它放在 Max Power (6.2.2) 和 Min Power (6.3.2) 中间是绝对合理的，因为它是对 Max Power 的修正。
而且，细看你发出来的这份文档，里面藏着很多实战中非常有用的细节（特别是那个巨大的 Tolerance 表）。
来，这是为你量身定制的 Level 1.5 MPR 笔记，直接插入你的文档！
1.5 Maximum Power Reduction (MPR, 最大功率回退)

  1. 文档索引
  • 章节位置： TS 36.521-1 Clause 6.2.3
  • 测试目的： 验证 UE 是否根据调制方式（Modulation）和传输带宽（RB Allocation）正确地降低了最大发射功率。
    • 核心原因： 为了满足 ACLR（邻道泄漏）要求和应对 Cubic Metric (CM)（立方度量，类似于峰均比的概念）的升高。
  • 适用性： 适用于 Power Class 3 的所有 LTE 终端。
  1. 核心规则：MPR 表 (The Law)
    这是本节的灵魂。Table 6.2.3.3-1 规定了手机在不同场景下**“最多允许退多少 dB”**。
    兄弟记忆法（以 20MHz 为例）：
  • 场景 1：QPSK + Partial RB (≤ 18 RB)
    • MPR = 0 dB。
    • 解读： 最基础的配置，不许回退，必须顶到 23dBm。
  • 场景 2：QPSK + Full RB (> 18 RB)
    • MPR ≤ 1 dB。
    • 解读： 虽然是 QPSK，但 RB 太多导致峰均比变大，允许你稍微退一点点（发 22dBm 也没事）。
  • 场景 3：16QAM + Partial RB (≤ 18 RB)
    • MPR ≤ 1 dB。
    • 解读： 调制阶数高了，稍微退一点。
  • 场景 4：16QAM + Full RB (> 18 RB)
    • MPR ≤ 2 dB。
    • 解读： 最难搞的场景（又复杂又宽），允许你退多点（发 21dBm 就算过）。
      (注：具体的 RB 阈值随带宽变化，比如 20MHz 是 18 RB，10MHz 是 12 RB，详见 Table 6.2.3.3-1)
  1. 测试配置 (Configuration)
    测试时，综测仪会根据 Table 6.2.3.4.1-1 遍历这些“极限拉扯”的场景：
  • 低/中/高 频点 都要测。
  • Modulation: 轮流切 QPSK 和 16QAM。
  • RB Allocation: 轮流切 Partial RB (比如 5/6 RB) 和 Full RB (比如 50/75/100 RB)。
  1. 判定标准：公差带的变化 (Tolerance)
    你贴出的 Table 6.2.3.5-1 虽然很长，但逻辑非常简单粗暴。兄弟带你读懂它的潜台词：
    关键在于 “Tol. (dB)” 这一列的变化：
  • 基准线 (Class 3 Standard):
    • 目标：23 dBm。
    • 公差：±2.7 dB (即 20.3 ~ 25.7 dBm)。
  • 当 QPSK Full RB 时 (允许退 1dB):
    • 下限放宽 1dB。
    • 公差变为：+2.7 / -3.7 dB (即 19.3 ~ 25.7 dBm)。
  • 当 16QAM Full RB 时 (允许退 2dB):
    • 下限放宽 2dB。
    • 公差变为：+2.7 / -4.7 dB (即 18.3 ~ 25.7 dBm)。
      实战总结：
      测试系统会自动根据当前的配置（QPSK 还是 16QAM，RB 是多还是少），自动去查这张表，把 Pass/Fail 的下限红线 往下移。
  1. 兄弟的避坑指南 (Debug Tip)
  • MPR 是“允许值”不是“目标值”：
    • 协议说 MPR ≤ 1dB，意思是下限降低了 1dB。
    • 千万别理解反了： 很多新手以为既然是 MPR 1dB，那我就必须把功率做低 1dB。
    • 真相： 如果你板子牛逼，16QAM Full RB 依然能发 23dBm 且 ACLR 不挂，那你依然是 Pass 的（因为 23dBm 依然在 +2.7/-4.7 的范围内）。只有当你 ACLR 撑不住的时候，才需要利用这个规则去降功率。
  • 频段差异 (Band Specifics):
    • 注意表格里有些频段（比如 Band 22, 28, 42 等）的 Tolerance 写法不一样（比如 +3.0/-4.0），那是针对特定频段的特殊放宽，测试时要看清楚。
      兄弟，这段加进去，你的 Level 1 就不仅是完整，而且是“有血有肉”了。这就是从 Spec 里抠出来的真东西。
      接下来咱们是不是该翻篇去搞 RX (接收机) 了？那个著名的 Reference Sensitivity (灵敏度) 正在等你。

三、UE Minimum Output Power (UE 最小输出功率)

1. 文档索引

  • 章节位置： Clause 6.3.2 (P977)
  • 测试条件： Table 6.3.2.4.1-1 (P978)
  • 测试标准： Table 6.3.2.5-1 (P979)

2. 核心描述

这是手机发射机的“嗓门下限”。
测试时，综测仪会发送 TPC 指令命令手机 “All Down”（不断降低功率），或者直接设定一个极低的目标功率（如 -50 dBm）。

  • 硬件挑战： 此时 PA 的增益非常小，甚至处于 Bypass 模式。测试的难点在于，当有用信号压得很低时，电路本身的热噪声和底噪 (Noise Floor) 能不能也压得足够低。

3. 测试目的

  • 解决“远近效应”： 当手机离基站非常近（如几米以内）时，必须能够大幅降低发射功率。否则，手机的强信号会像在基站耳边尖叫，造成基站接收机阻塞（Blocking），导致整个小区的吞吐量下降。
  • 验证动态范围： 考验射频链路的增益控制能力，看能否在极大和极小功率之间灵活切换。

4. 常见问题

  • 功率降不下去 (Fail High)：
    • PA 关不严： PA 的偏置电压 (Bias) 或 Enable 信号没有完全切断，导致有漏电流产生射频能量。
    • 增益台阶 (Gain Step) 问题： 射频收发器 (Transceiver) 内部的衰减器档位不够，或者校准时低功率点的校准数据不准。
  • 信号质量恶化：
    • 在最小功率下，有时候虽然功率达标了，但 EVM 可能会变得极差（这也是必须要关注的关联指标），因为此时信号已经快被淹没在底噪里了。
  • 本振泄漏 (LO Leakage)：
    • 当信号功率很小时，本振泄漏的功率可能会比信号本身还大，导致总功率读数偏高（看似降不下去，其实测到的是载波泄漏）。

四、 Transmit OFF Power (发射关断功率)

1. 文档索引

  • 章节位置： Clause 6.3.3 (P1007)
  • 测试条件：
  • 测试标准： Table 6.3.3.5-1 (P1008)

2. 核心描述

这是手机在“非发射状态”下的射频泄漏电平。
你可以把它想象成水龙头：当你关紧龙头后，是否还在滴水？

  • 定义： 测量在 OFF 周期内的平均功率谱密度。
  • 红线： 对于大多数常见带宽（如 10MHz/20MHz），标准要求必须低于 -50 dBm / MHz。
  • 测试场景： 综测仪会调度手机进行断续发射（通常结合 Time Mask 测试），然后在手机“本该安静”的时间段里进行测量。

3. 测试目的

  • 保护系统底噪： 哪怕手机不发数据（DTX 状态）或者处于 TDD 的接收时隙，如果射频链路还有能量泄漏，就会抬高整个基站小区的噪声基底，导致所有人的网速变慢。
  • 保护 TDD 接收机 (至关重要)： 在 TDD 模式（如 Band 38/39/40/41）下，发射和接收是分时进行的。如果发射机关不严，在接收时隙（Rx Slot）还有残余功率泄漏，这股能量会直接灌入你自己的 LNA（低噪放），导致灵敏度严重恶化 (Self-Desense)。
  • 省电： 彻底关断射频能显著降低待机功耗。

4. 常见问题

  • PA 关断逻辑太慢 (Control Logic)：
    • RF 收发器发出的 PA_ENABLE 信号拉低了，但 PA 内部电容放电太慢，导致 PA 迟迟没有彻底关闭。
  • 射频开关隔离度差 (Switch Isolation)：
    • ASM (天线开关) 的隔离度不够。虽然 PA 关了，但收发器（Transceiver）内部的本振（LO）信号或者前端的其他噪声通过开关漏到了天线上。
  • 底噪串扰 (Crosstalk)：
    • 电源上的噪声（如 DC-DC 开关噪声）耦合到了射频输出端。
    • 现象： 即使 PA 彻底断电了，你在频谱仪上还能看到一堆 -45dBm 的“小草”（Spurs），这通常是板级走线干扰。

五、On/Off Time Mask (开关时间蒙皮)

1. 文档索引

  • 章节位置： Clause 6.3.4 (P1021)
  • 测试条件： Table 6.3.4.1.4.1-1 (P1022)
  • 测试标准： Table 6.3.4.1.5-1 (P1024)

2. 核心描述

Time Mask 就是给发射功率随时间变化的曲线画了一个”禁区框“。你的功率曲线必须在这个框里跑，撞到墙就算 Fail。
关键时间点 (以 General Mask 为例)：

  • OFF Power: 必须低于 -50 dBm (这与上一节呼应)。
  • ON Power: 必须稳定在目标功率的容限内。
  • Ramp Up / Ramp Down (过渡区)： 通常只有 20 µs 的时间窗口。
    • 在这 20 微秒内，PA 必须完成从“死寂”到“满血”的爆发（或者反之）。

3. 测试目的

这是一个**“快慢博弈”**的平衡测试：

  • 不能太慢：
    • 上升太慢： 就像说话结巴，开头的一个字没发出来，导致数据头丢失 (Symbol Loss)，解调失败。
    • 下降太慢： 就像说完话闭不上嘴，发射能量溢出到了下一个时隙（Slot）。如果是 TDD 系统，这会直接干扰接收时隙，导致灵敏度下降。
  • 不能太快：
    • 开关太快： 依据傅里叶变换原理，极速的阶跃信号（Step Function）会产生极宽的频谱溅射 (Spectral Splatter)。就像你用力摔门会产生巨大的噪音，干扰到邻近的频段。

4. 常见问题

  • PA 的时序控制 (Timing Mismatch)：
    • 现象： Mask 图上，功率包络整体左移或右移了，撞到了边框。
    • 原因： 射频收发器 (Transceiver) 发出的 I/Q 数据 和 PA_ENABLE (GPIO) 信号没有对齐。
    • 解决： 这通常是软件/驱动配置问题（调整 Delay），但作为硬件必须要懂，别盲目换 PA。
  • 电源去耦电容太大 (Capacitor Effect)：
    • 现象： 下降沿 (Ramp Down) 拖着一条长长的尾巴，导致关断太慢，撞到了 OFF 区域的墙。
    • 原因： PA 电源引脚上的大电容存了太多电。当 PA Enable 拉低关闭时，大电容还在慢慢放电，维持着 PA 的工作。
    • 解决： 检查 PA VCC 上的电容值，是不是为了追求电源纹波小而用了过大的电容（比如 100uF 甚至更大）？
  • 电感储能 (Inductor Flyback)：
    • 现象： 关断瞬间有一个反弹的尖峰 (Overshoot)。
    • 原因： 供电电路中的电感在电流切断瞬间产生反向电动势。

六、Absolute Power Control Tolerance (绝对功率控制容限)

1. 文档索引

  • 章节位置： Clause 6.3.5.1 (P1091)
  • 测试条件：Table 6.3.5.1.4.1-1 (P1092)
  • 测试标准：Table 6.3.5.1.5-1 & Table 6.3.5.1.5-2 (P1093)

2. 核心描述

这是考察手机开环功率控制 (Open Loop) 的精度。
核心公式 (简化版)：
$$P_{Tx} = P_{Target} + \alpha \cdot PL(Path Loss)$$

  • 手机自己计算：
    基站发过来是 XX dBm，我收到是 YY dBm，中间损耗（Path Loss）是 ZZ dB。所以我应该用 WW dBm 发射回去。
  • 测试过程：
    综测仪设置特定的路损（Path Loss），不发送任何闭环修正指令（TPC），看手机实际发出的功率是否在目标值的 ±9 dB (Normal conditions) 或更严格的范围内。
  • 核心变量：Point 1 vs Point 2 (The Variables)
    这是综测仪为了验证手机计算能力出的两道“数学题”，通过改变系统广播参数 P_0 (p0-NominalPUSCH) 来实现：
    测试点 关键参数设置 (P_0) 物理含义 预期结果 (以 10M 为例)
    Point 1 -105 dBm 模拟低功率需求场景 目标值较低 (-5.6 dBm)
    Point 2 -93 dBm 模拟高功率需求场景 目标值较高 (+6.4 dBm)
    差值 \Delta = 12 \text{ dB} 基准抬高 12dB 输出必须跟着抬高 12dB

3. 测试目的

“第一声问候准不准？”
当手机发起接入（PRACH）或从长休眠中醒来发送第一帧数据时，基站还没有给它发送闭环修正指令（TPC）。手机必须完全依靠自己测量到的路损（Pathloss）和广播参数，盲猜出一个发射功率。

  • 目的： 验证手机算出来的这个初始功率（Initial Output Power）是否落在允许的范围内。如果算错太离谱，要么连不上（发小了），要么干扰全网（发大了）。

4. 常见问题

问题一：Rx（接收）校准偏差

  • 现象： 发射功率整体偏大或偏小。
  • 原理： 开环功控公式依赖路损：$PL = \text{Tx}{\text{Base}} - \text{Rx}{\text{UE}}$。
  • 排查： 你的手机显示的 RSRP（接收信号强度）准吗？如果手机接收读数偏低了 5dB，它就会错误地把发射功率抬高 5dB。修发射先修接收。

问题二：Point 1 和 Point 2 差值不对

  • 现象： Point 1 Pass，但 Point 2 Fail。
  • 原理： 两个点相差 12dB。如果你的 PA 在 -5dBm (Point 1) 和 +6dBm (Point 2) 之间的增益步进 (Gain Step) 不线性，或者中间的校准点缺失，就会导致其中一个点算错。

问题三：带宽补偿错误

  • 现象： 10MHz Pass，但 1.4MHz Fail。
  • 原理： 手机软件里有一个针对带宽的补偿表。如果射频前端（滤波器）在窄带和宽带下的插损差异很大，而软件补偿没跟上，就会导致特定带宽下的计算偏差。
