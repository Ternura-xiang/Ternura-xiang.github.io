LTE 3GPP指标(3) - 灵敏度 (Sensitivity)

分类： 学习笔记
标签： 3GPPLTE

日期：2026-01-23 00:12:03

[toc]

总览

Level 3: 挑战级 - 听力测试 (Rx)
关键词： 灵敏度 (Sensitivity)
涉及章节： 36.101 Clause 7.3
开始进入接收机 (Rx) 领域。这时候你要对抗的不是外部，而是你自己的板子。

指标名称 中文名 难度 一句话解释 硬件看什么
Reference Sensitivity 参考灵敏度 ⭐⭐⭐ 只有微弱信号时，手机能听清吗？ Desense 之源！ 检查 LNA（低噪放）、滤波器插损，以及屏幕/DDR/Camera 的噪声干扰。
Max Input Level 最大输入电平 ⭐⭐ 在基站塔下（信号极强）会被震聋吗？ 检查 LNA 的 Bypass 模式或 AGC 增益切换是否正常。
  • 通关标志： 传导灵敏度能达到 -97dBm (举例) 且没有明显的坏点。

一、Reference Sensitivity Level (参考灵敏度)

1. 文档索引

  • 章节位置：Clause 7.3 (P2412)
  • 判定标准：Table 7.3.3-1/1a/1aa (P2413)
    • QPSK 调制（这是最基础的抗干扰模式，用来测极限）。
    • Full RB（通常要求满带宽，因为带宽越宽，底噪越高，越难接收）。
    • Throughput > 95%。意思是综测仪发给你 1000 个包，你至少要能正确解调 950 个。如果丢包超过 5%，就算听不清了。

2. 核心描述

“听力底线”。
这是衡量手机“耳朵”最灵敏能听到多小声音的指标。
综测仪会把发射功率越调越低（比如从 -70dBm 降到 -90dBm，再到 -95dBm…），直到手机开始出现丢包（误码率上升）。那个丢包率刚刚达到 5% 的临界点功率，就是你的灵敏度。

  • 直观感受： LTE 的灵敏度通常在 -94 dBm 到 -100 dBm 级别。这相当于微弱到只有 0.0000000001 mW 的能量。

3. 核心公式：为什么带宽越大越难测？

这个公式是硬件工程师必须要刻在脑子里的，分析 Rx 问题全靠它：

  • -174 dBm/Hz: 这是物理极限（热噪声基底），改不了的。
  • 10log(BW): 带宽带来的噪声。
    • 带宽越大，进来的噪声越多。
    • 例子： 10MHz 带宽的底噪天生就比 1.4MHz 带宽的高大约 8.5dB。所以 20MHz 的灵敏度指标一定比 5MHz 的难做。
  • NF (Noise Figure, 噪声系数): 这是你的硬件水平。
    • LNA（低噪声放大器）、Saw Filter（声表滤波器）、走线插损加起来产生的额外噪声。NF 越小越好。
  • SNR_min: 解调 QPSK 所需的最小信噪比（由基带算法决定，通常是固定的）。

4. 常见问题

灵敏度挂了，通常就两种情况：要么是外面吵，要么是自己聋。
情况 A：Desense (自干扰 / 接收灵敏度恶化)

  • 现象： 传导测试（插线测）还好，一做整机（OTA）或者亮屏就挂。或者某个特定频点突然很差。
  • 原因： 板子上的噪声串进来了。
    • 电源干扰： DC-DC 的开关频率正好落在了这个频段里。
    • 时钟谐波： 屏幕、摄像头、内存（DDR）的时钟倍频，正好等于射频接收频率。
    • 排查： 拿频谱仪探头在板子上扫，看有没有不该出现的“刺”。

情况 B：链路插损太大 (Loss Issue)

  • 现象： 所有频点都整体偏差 2-3dB。
  • 原因： 从天线弹片到 Transceiver 这一路上损耗太大了。
    • 检查匹配电路电感电容是不是焊错了值（Q值不够？）。
    • Saw Filter 是不是选错了频段（带外抑制太大，导致带内插损也大）？
    • 射频线是不是被压扁了？
      情况 C：LNA 没工作
  • 现象： 灵敏度极差（比如只有 -50dBm），甚至根本连不上。
  • 原因： 接收链路里的 LNA 没供电，或者 LNA 击穿了。

5. 总结

测试灵敏度，本质上是在测**“信噪比 (SNR)”**。

  • 信号 (S) 是综测仪给的（越来越小）。
  • 噪声 (N) 是你板子自己产生的（热噪声 + 干扰）。
    要想灵敏度好，只有两条路：
  • 降低链路损耗（让 S 尽可能大保留）。
  • 做好屏蔽和滤波（让 N 尽可能小）。
    这里有个非常有意思的细节：Full RB 的灵敏度是最难的，这跟发射那边 Max Power 的逻辑正好呼应上（都是宽带最难搞）。

二、Maximum Input Level (最大输入电平)

1. 文档索引

  • 章节位置： Clause 7.4 (P2821)
  • 测试标准： Table 7.4.3-1 (P2821)
    • 功率： 给手机灌一个巨响的信号，通常是 -25 dBm (有些频段略有不同)。
    • 配置： 64QAM 满带宽 (Full RB)。为什么要用 64QAM？因为高阶调制对“失真”最敏感，只要电路稍微有一点点饱和，64QAM 马上就解不出来了。
    • Throughput > 95% (依然是那个熟悉的标准，只要不丢包就算赢)。

2. 核心描述

“防止被吼聋”。
想象一下，你站在演唱会的音箱正对面，或者你就在基站的天线底下（塔下黑）：

  • 信号能量极其巨大。
  • 如果你的手机像测灵敏度时那样，把耳朵竖得尖尖的（LNA 增益全开），瞬间就会被震聋。
  • 物理现象： 这叫 饱和 (Saturation) 或者 削顶 (Clipping)。LNA (低噪声放大器) 和 ADC (模数转换器) 都有输入上限，超过这个限度，正弦波就被切成了方波，信号全废了。

3. 核心机制：AGC (Automatic Gain Control)

这个测试项的核心不在于“扛”，而在于“变”。
手机是怎么过这一关的？靠的是 AGC (自动增益控制) 策略。

  • 灵敏度模式 (High Gain Mode): 信号弱 -> LNA 打开，放大倍数 max。
  • 最大输入模式 (Low Gain/Bypass Mode): 信号强 -> 手机检测到 -25 dBm 的强信号，立马下令：“太吵了！把 LNA 关掉！或者走旁路 (Bypass)！”
    所以，这个测试本质上是在测：你的 LNA 增益切换策略 (Gain Switching) 灵不灵？

4. 常见问题

这就比灵敏度简单多了，挂了通常就是软件配置问题。
情况 A：软件“反应迟钝” (Hysteresis Issue)

  • 现象： 信号从 -90 升到 -25 的过程中，手机丢包了。
  • 原因： 切换阈值没设好。
    • 比如：如果你设定 -30dBm 才切低增益，那在 -35dBm 到 -30dBm 这个区间，LNA 还开着高增益，但信号已经把电路撑爆了。

情况 B：ADC 动态范围不够

  • 现象： 即使 LNA 关了 (Bypass)，还是解调失败。
  • 原因： 信号直通进来了，还是太强，把后面的 ADC (模数转换器) 给灌满了。这时候通常需要加额外的衰减器 (Attenuator)。
    情况 C：SAW Filter 承受不住
  • 现象： 极其罕见，但也有。如果是那种几十瓦的基站模拟测试，可能会把前端的滤波器烧坏（当然 -25dBm 还不至于）。

三、总结

把 Level 3.1 和 Level 3.2 放在一起看，你就懂了接收机的“生存哲学”：

  • Reference Sensitivity (-95 dBm): 考验的是“静”。要在极度安静中听清蚊子叫。 -> 难点是降噪。
  • Max Input Level (-25 dBm): 考验的是“变”。要在巨大轰鸣中甚至要把耳朵堵上才能听清。 -> 难点是线性度和 AGC 策略。
    这一关相对轻松，通常只要软件里的 LNA Gain Table 填对了，都能过。
